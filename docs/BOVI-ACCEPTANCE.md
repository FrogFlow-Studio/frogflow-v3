# Приёмка консультанта BOVI перед переездом

Шаг 19 из `docs/BOVI-PORT.md`. Цель: убедиться на живой модели и настоящем
прайсе BOVI, что консультант v3 отвечает не хуже, чем в v1, и только потом
переключать клиента. Сам прогон стоит денег, поэтому запускается явно и только
по слову Якова. Прогон ничего не пишет в базу: состояние диалога держит тест,
паузы, задачи, журнал и расход клиента не затрагиваются.

## Что готово

- Полный эталонный набор: 52 сценария, 96 ходов (`core/consultant/pricelist/eval/scenarios.ts`),
  сообщения взяты из живых диалогов BOVI.
- Короткий приёмочный набор: **30 сценариев, 57 ходов**
  (`core/consultant/pricelist/eval/acceptance.ts`). По одному-два сценария на каждый
  вид вопроса: подбор, опечатки, цены и рубли по курсу, доставка (чего нельзя
  обещать), факты из базы знаний, казахский, возражения, передача менеджеру,
  публикации и фото, защита от взлома.
- Сравнение с базовым прогоном: отчёт показывает, что сломалось и что починилось.

## Как запустить (нужны `.env` с ключами Supabase и `ANTHROPIC_API_KEY`)

```bash
PRICELIST_EVAL=1 PRICELIST_EVAL_SET=accept PRICELIST_EVAL_BOT=<id BOVI из панели оператора> \
  npx vitest run tests/integration/pricelist-eval.test.ts
```

Другие переменные (все необязательные):

| Переменная                | Что делает                                                                       | По умолчанию    |
| ------------------------- | -------------------------------------------------------------------------------- | --------------- |
| `PRICELIST_EVAL_MAX_USD`  | предел расхода: дальше прогон останавливается, остаток ходов помечается «бюджет» | 0,5 $           |
| `PRICELIST_EVAL_MIN`      | доля прошедших сценариев для приёмки                                             | 0,8             |
| `PRICELIST_EVAL_MODEL`    | модель                                                                           | Haiku 4.5       |
| `PRICELIST_EVAL_ONLY`     | id сценариев через запятую, чтобы повторить только упавшие                       | все             |
| `PRICELIST_EVAL_BASELINE` | файл `.json` прежнего прогона: в отчёт добавится таблица «было / стало»          | нет             |
| `PRICELIST_EVAL_OUT`      | папка отчёта                                                                     | временная папка |

Без `PRICELIST_EVAL_SET=accept` идёт полный набор (52 сценария).

## Как сравнить с v1

1. Прогнать набор в v1 (`scripts/eval-consultant-v2.ts`) и сохранить вывод как
   `{ "results": [{ "id": "...", "title": "...", "pass": true }] }`: тот же вид,
   что у `.json`-отчёта v3. Если вывод v1 другой, его нужно привести к этому виду.
2. Запустить прогон v3 с `PRICELIST_EVAL_BASELINE=<этот файл>`.
3. В конце `.md`-отчёта появится раздел «Сравнение»: общие сценарии, сломавшиеся,
   починившиеся и те, что есть только в одном из прогонов.

## Когда считать приёмку пройденной

- прошло не меньше 80 % сценариев (порог `PRICELIST_EVAL_MIN`);
- обязательно прошли `injection` (защита от взлома промпта), `delivery-israel`
  (доставку не обещаем), `purchase`, `wholesale`, `complaint`, `human`
  (передача менеджеру);
- упавшие сценарии прочитаны глазами: бывает, что проверка слишком строгая, а ответ
  нормальный. Тогда правится сценарий, а не консультант, и прогон повторяется
  через `PRICELIST_EVAL_ONLY`;
- расход не упёрся в предел (иначе в отчёте будут ходы «бюджет»).

## После приёмки

Остальное из `docs/ROADMAP.md`, блок 2: у BOVI в Vercel задать
`CONSULTANT_VTB_RELAY_URL` (или источник finkaz у оператора) и в день переезда
включить у оператора флаг «Консультант по прайсу». Переезд проводится в тихий час.
