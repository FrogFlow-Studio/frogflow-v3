# Миграции партии 19

Все миграции партии — только добавляющие (`CREATE TABLE IF NOT EXISTS`, политики, права): существующие таблицы v1 не меняются и не удаляются. Каждая лежит в `migrations/19-<n>-<имя>.sql` с парой `.down.sql`. **В базу их применяет только Яков, своим словом**; код работает и без них — раздел отвечает «скоро», ошибок нет (у каждой миграции есть тест на отсутствие таблицы).

Порядок независим друг от друга: таблицы между собой не связаны (внешние ключи — только на `bots`). Рекомендуемый порядок — по номеру. Применять в SQL-редакторе Supabase, по одному файлу, после каждого — проверка из таблицы ниже.

## Права и RLS

- `19-13`: RLS по `current_bot_id()`, у `tenant_bot` `SELECT` и `INSERT` своих строк, `bot_id` принудительно ставит триггер `force_bot_id`.
- `19-7`, `19-8`: RLS по `current_bot_id()`, у `tenant_bot` только `SELECT` своих строк; запись и публичные страницы площадки — под `service_role`.
- `19-1`, `19-5`: включена RLS, политики через `current_bot_id()`; роль `tenant_bot` получает только нужные права (в поддержке — чтение/вставка и обновление нескольких полей; `platform_thread_notes` — внутренние заметки оператора, у `tenant_bot` прав нет; в новостях — чтение опубликованных и вставка своих прочтений и голосов).
- `19-2`, `19-3`, `19-4`: RLS включена **без политик** — доступ только у `service_role`. Данные общие для авторов, поэтому код ходит через `serviceDb()` и до любой операции проверяет согласие автора (`takesPartInCommunity`, `dmVerdict`).

## Проверка после применения

Ничего не писать в чужие данные; проверять на «Демо-тестере».

1. `select count(*) from <таблица>;` — запрос проходит (ноль строк — норма).
2. `select relrowsecurity from pg_class where relname = '<таблица>';` — `true`.
3. В админке «Демо-тестера» открыть раздел (поддержка, сообщество, «Что нового») — вместо «скоро» открывается рабочий экран; у оператора — очередь обращений, жалобы, редактор новостей.
4. Для `19-1`: написать из админки сообщение — оно появляется в очереди оператора. Для `19-3`: уведомление о личном сообщении уходит один раз (метка `notified_at`).

## Откат

Откат — соответствующий `.down.sql`. Он удаляет таблицы вместе с данными, поэтому сначала выгрузить нужное. После отката раздел снова отвечает «скоро», код менять не нужно.
