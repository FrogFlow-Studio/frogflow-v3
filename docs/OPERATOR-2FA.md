# Двухшаговый вход оператора

После пароля панель оператора спрашивает шестизначный код из
приложения-аутентификатора на телефоне (Google Authenticator, Microsoft
Authenticator и подобные) или один из резервных кодов. По умолчанию выключен.

## Как включить

«Настройки» → «Двухшаговый вход» → «Включить». Отсканировать QR-код
приложением (или ввести ключ вручную) и ввести код из приложения. Защита
включается только после верного кода. Сразу показываются 10 резервных кодов —
один раз; их нужно сохранить (распечатать или записать). Каждый срабатывает
один раз вместо кода из приложения.

Включение и выключение завершает все прочие сессии оператора; текущая остаётся.

## Где хранится

Таблица `operator_settings` (схема не менялась):

| ключ                      | что                                                                         |
| ------------------------- | --------------------------------------------------------------------------- |
| `operator_totp_secret`    | секрет приложения, зашифрован `SECRETS_KEY`. Есть строка — вход требует код |
| `operator_totp_pending`   | секрет на время включения, до первого верного кода (15 минут)               |
| `operator_totp_last_step` | шаг последнего принятого кода: тот же код второй раз не пускает             |
| `operator_backup_codes`   | JSON-массив SHA-256 хэшей резервных кодов                                   |
| `operator_session_epoch`  | эпоха сессий: новая при каждом включении и выключении, входит в отпечаток   |

Код — `src/app/operator/two-factor.server.ts`, расчёт кодов (RFC 6238) —
`src/core/auth/totp.ts`.

## Если потеряны и телефон, и резервные коды

Выполняется только по прямому слову Якова. Нужен доступ к базе с ключом
платформы (сессия «Живой прогон» или SQL-редактор Supabase).

1. Удалить строки двухшагового входа — только эти четыре ключа, ничего больше.
   `operator_session_epoch` **не удалять**: без неё отпечаток вернулся бы к
   тому, что был до первого включения, и старые (возможно, украденные) cookie
   ожили бы.

   ```sql
   delete from operator_settings
   where key in (
     'operator_totp_secret',
     'operator_totp_pending',
     'operator_totp_last_step',
     'operator_backup_codes'
   );
   ```

   Через API (supabase-js под ключом платформы) — то же:
   `from("operator_settings").delete().in("key", [...четыре ключа...])`.

2. Вход снова только по логину и паролю. Все прежние сессии оператора после
   этого сами завершатся (из отпечатка ушёл секрет, а эпоха осталась новой —
   сессии и до включения, и при включённом входе не совпадут).
3. Сразу войти и включить двухшаговый вход заново с новым телефоном.

Пароль при этом не меняется. Если пароль тоже мог утечь — сменить его в
«Настройках» после входа.
