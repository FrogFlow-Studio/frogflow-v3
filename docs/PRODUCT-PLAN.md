# FrogFlow v2 — максимальный план

Цель: платформа, к которой продавец подключается сам за десять минут, продаёт
в Telegram, Instagram, WhatsApp и на сайте из одной админки, не теряет ни
одного сообщения и заказа, а оператор видит всех клиентов и деньги без
Vercel, таблиц и ручных переменных. Ниже — всё, что для этого нужно, от
самого важного к желаемому. Каждый пункт помечен: **P0** — без этого v2 не
лучше v1, **P1** — заметный отрыв, **P2** — превосходство.

Точка отсчёта — v1: 21 из 35 модулей прайса не построены (312 000 ₸ по
прайсу), рассылки за всё время не отправлены ни разу, 69 сообщений Instagram
потеряны в `pending`, продавец видит расход ИИ без понятного счёта, а
оператор подключает клиента через проект Vercel и блок переменных.

## Мерила «топовости»

| мерило                                   | v1 сегодня     | цель v2                        |
| ---------------------------------------- | -------------- | ------------------------------ |
| подключение нового магазина              | оператор, ~1 ч | сам, 10 минут                  |
| первый заказ после подключения           | дни            | в тот же день                  |
| действий продавца на один заказ          | 4–6            | 1–2                            |
| потерянных сообщений и заказов           | есть           | 0, с доказательством в журнале |
| каналов из одной админки                 | по одному      | все                            |
| время ответа покупателю ботом            | секунды–минуты | < 2 секунд                     |
| языков интерфейса продавца               | ru             | ru, kk, en, uz                 |
| доля дохода платформы с самообслуживания | 0              | > 50 %                         |

## 1. Подключение и первый день (P0)

- **Самостоятельная регистрация** продавца: почта или Telegram-логин,
  название, ниша → магазин создан, пробный период включён. Оператор
  подключает только если сам захотел.
- **Мастер первого запуска** внутри админки, чеклист с прогрессом:
  подключить бота (вставил токен — готово, вебхук ставится сам), реквизиты
  оплаты, первый товар, тестовый заказ на себя. Каждый шаг с подсказкой и
  видео на 30 секунд.
- **Шаблоны ниши**: цифровые материалы, кондитерская, цветы, консультант,
  курсы. Шаблон включает модули, тексты бота, категории-примеры, демо-товар.
- **Импорт каталога**: Excel/CSV с автосопоставлением колонок, Google Sheets
  по ссылке с автообновлением, перенос из Instagram (посты → товары с фото и
  ценой из подписи), из v1 одной кнопкой.
- **Живой предпросмотр бота** в админке: справа виден чат, как его увидит
  покупатель, меняешь текст — видишь сразу.

## 2. Каналы продаж (P0/P1)

- **Telegram** ✔ бот + **Mini App** (P0): каталог с поиском и фильтрами,
  корзина, оформление в два экрана, оплата картой, история заказов,
  библиотека купленных материалов. Кнопка «Магазин» в меню бота.
- **Instagram Direct и комментарии** (P0): магазин по номеру товара,
  comment-to-DM, быстрые ответы, продажа по чеку с выдачей на почту,
  сторис с тегом товара.
- **WhatsApp** (P0): каталог списками, шаблоны Meta вне 24-часового окна,
  активация словом.
- **Сайт-витрина** `/s/<адрес>` и **свой домен** (P1): SEO, OG-карточки для
  постов, быстрая, PWA. Покупка на сайте без перехода в бота, либо перенос
  корзины в Telegram одним тапом.
- **Единый покупатель** (P1): человек, написавший в Instagram и потом в
  Telegram, один профиль — по телефону/почте, с историей во всех каналах.
- **Telegram Web Login на сайте** (P2): войти на витрину через Telegram и
  видеть свои заказы.

## 3. Оплата (P0/P1)

- **Kaspi Pay и Kaspi QR** (P0) — главный способ в Казахстане: ссылка на
  оплату, автоматическое подтверждение через API там, где оно есть.
- **Robokassa** (P0, перенос из v1), **Telegram Stars** (P1), **крипта**
  (P2, NOWPayments), **PayPal/Stripe** для покупателей из-за рубежа (P2).
- **Чек с автопроверкой** (P0): OCR, сверка суммы и получателя,
  автовыдача при совпадении, повтор того же чека блокируется.
- **Частичная оплата и задаток** (P1) для физических товаров, доплата при
  получении, история платежей по заказу.
- **Возвраты** (P1): фиксация возврата, статус, уведомление покупателю,
  возврат баллов и промокодов.
- **Счета оператора продавцу** (P1): автоматически по тарифу, оплата
  картой, напоминания, пауза при просрочке по политике — перенос из v1 без
  ручных шагов.

## 4. Заказы и выполнение (P0/P1)

- **Единая лента заказов** из всех каналов, статусы одной кнопкой, чек
  рядом, быстрые действия с клавиатуры. Живое обновление без перезагрузки
  (Supabase Realtime).
- **Push и Telegram-уведомления продавцу** о новом заказе с кнопками
  «выдать/отклонить» (P0, есть в боте; добавить push в PWA-админку).
- **Физические товары** (P0, перенос): самовывоз/доставка, зоны с ценой,
  дата и слоты, срок изготовления, напоминание за день, надпись на торте,
  фото готового заказа на согласование (из `flowers.ts`).
- **Курьер** (P2): передача заказа в Яндекс Доставку/inDrive по API, трек.
- **Печать** (P2): бланк заказа и наклейка на коробку одной кнопкой.
- **Цифровая выдача** ✔: файлы по языкам, ссылка на страницу материалов,
  повторная выдача, библиотека у покупателя; водяной знак с именем
  покупателя на PDF (P2) против перепродажи.

## 5. Единый входящий (P1)

Один экран всех диалогов Telegram, Instagram, WhatsApp: очередь
непрочитанных, перехват у бота, быстрые ответы, шаблоны, вложения, назначение
на менеджера, пометка «решено». Бот молчит, пока говорит человек, и сам
возобновляется через N минут. Заказ создаётся прямо из диалога («выставить
счёт»). Это заменяет и `manager_chat`, и `helpdesk` из прайса.

## 6. Покупатели и удержание (P1)

- **CRM-профиль**: заказы, диалоги, суммы, баллы, теги, заметки, LTV, откуда
  пришёл (deep link, пост, сторис).
- **Сегменты**: купившие X, не покупали 60 дней, из страны, по языку, с
  брошенной корзиной — и рассылка по сегменту.
- **Рассылки** с расписанием, картинками, кнопками на товары, A/B текста,
  отчётом по доставке и кликам, ограничением частоты. В v1 рассылок не было
  отправлено ни одной — в v2 они должны быть очевидными.
- **Автоворонки**: брошенная корзина (есть в v1), winback, после покупки
  через N дней «похожие материалы», день рождения, серия после `/start`.
- **Лояльность и рефералка** (перенос): баллы, уровни, приглашение друга.
- **Отзывы** с фото, ответ продавца, показ в карточке и на витрине.

## 7. ИИ везде, где он экономит время (P1/P2)

- **Консультант** во всех каналах (перенос BOVI и универсального): отвечает
  по каталогу и базе знаний, знает остатки и цены, передаёт менеджеру,
  молчит, когда говорит человек. Настройка тоном и правилами в админке,
  тест-чат прямо там.
- **Умный поиск** по каталогу (перенос) и **подбор** «под бюджет и запрос».
- **Помощник продавца** в админке (P2): «напиши описание товара»,
  «сгенерируй пост для Instagram», «ответь на этот отзыв», «объясни, почему
  упали продажи».
- **Автотеги и категории** при импорте, распознавание чеков ✔.
- **Прозрачный счёт за ИИ**: расход в токенах и тенге по дням, лимиты,
  предоплата. v1 считал это правильно после трёх правок — сохраняем логику.

## 8. Аналитика (P1)

Дашборд с графиками: выручка по дням/каналам, воронка (открыл → корзина →
заказ → оплата), топ товаров, повторные покупки, когорты, средний чек,
время до оплаты, доля выдач без участия продавца. Экспорт в Excel и Google
Sheets, еженедельный дайджест в Telegram и на почту. Для оператора — то же
по всем клиентам плюс MRR, churn, расход ИИ по клиентам.

## 9. Маркетинг и каталог (P1/P2)

Промокоды (перенос), подарочные сертификаты (перенос), наборы и апселл
«с этим берут», ограниченные предложения с таймером, лист ожидания при
нулевом остатке, вариации с остатком по каждой, товары-подписки (курсы с
ежемесячной оплатой, VIP-группа — перенос VIP-бота как обычного модуля),
цифровые товары с предпросмотром, скрытые товары по ссылке.

## 10. Команда, безопасность, доверие (P1)

- **Несколько пользователей** у магазина, роли: владелец, менеджер,
  бухгалтер; журнал действий; вход по Telegram; 2FA для оператора.
- **Аудит**: кто изменил цену, кто выдал заказ, кто написал покупателю.
- **Данные**: экспорт всего одним архивом, удаление магазина с холдом 30
  дней, шифрование секретов ✔, изоляция арендаторов на уровне Postgres ✔.
- **Юридические страницы** магазина из шаблонов (оферта, политика,
  реквизиты) с подстановкой данных.

## 11. Платформа и надёжность (P0)

То, что в v1 ломалось у живых клиентов, в v2 закрывается архитектурой:

- **Очередь задач в Postgres** (таблица `jobs`, захват `FOR UPDATE SKIP
LOCKED`, повторы с backoff, dead-letter): выдача файлов, рассылки,
  напоминания, ретраи Zernio, письма. Serverless без очереди — это и есть
  «69 потерянных сообщений».
- **Исходящий outbox** для всех сообщений в каналы: каждое отправляемое
  сообщение сначала записано, потом отправлено, с `Idempotency-Key` —
  никаких дублей и никакого «сказал ли бот это».
- **Журнал событий** каждого арендатора (заказ создан, чек получен, файл
  выдан, сообщение доставлено) — то, что продавец видит в карточке заказа
  как таймлайн, а оператор — как доказательство.
- **Наблюдаемость**: ошибки с контекстом арендатора (Sentry), трассировка
  запроса вебхука до ответа, здоровье каждого бота и аккаунта Zernio на
  панели, страница статуса.
- **Тесты**: ядро по описи v1 (1074 проверки — переносятся вместе с
  функциями), интеграционные на живой базе ✔, браузерные сценарии
  оператора и продавца ✔ в CI, предпросмотр каждого PR.
- **Rate limits** на вебхуках и Mini App с общим хранилищем, а не
  per-instance.
- **Локализация продавца**: kk/en/uz в админке и Mini App, язык переживает
  SSR, валюты и форматы дат по стране.
- После выключения v1 — **схема без наследия**: `bot_users.telegram_id`
  как синтетический ключ, глобальная последовательность `orders.id`,
  `story_product_tags` без RLS — всё выправляется миграциями.

## 12. Оператор и деньги платформы (P1)

- **Тарифы и модули на самообслуживании**: продавец включает модуль сам,
  платит картой, счёт и акт генерируются; оператор видит MRR, просрочки,
  расход ИИ, заявки. Модуль в каталоге = страница с описанием, скриншотом
  и кнопкой «попробовать 14 дней».
- **Здоровье клиентов**: последний заказ, ответы бота, ошибки, отвалившиеся
  аккаунты — сигналы, а не таблица на 40 колонок.
- **Партнёрка** (P2): агентства подключают клиентов и получают долю.
- **Публичный API и вебхуки** (P2) для 1С, CRM, Google Sheets, Zapier.

## 13. Интерфейс (P0 сквозной)

Одна дизайн-система ✔, тёмная тема ✔, телефон ✔. Дальше: командная палитра
(⌘K: найти заказ, товар, покупателя), горячие клавиши в заказах, пустые
состояния с действием, скелетоны вместо спиннеров, undo для удалений,
автосохранение форм, drag-and-drop порядка товаров и категорий,
предпросмотр карточки товара как в боте и на витрине, PWA-установка
админки на телефон с push.

## Порядок работ

| этап | что                                                                                                 | результат                                              |
| ---- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| A    | очередь и outbox, физические товары, промокоды/баллы/сертификаты, Robokassa, OCR, Mini App, витрина | продавец цифровых и физических товаров полностью на v2 |
| B    | Instagram и WhatsApp, единый входящий, консультант, Kaspi                                           | все каналы из одной админки                            |
| C    | регистрация и мастер, шаблоны ниш, импорт, тарифы на самообслуживании, локализация                  | рост без оператора                                     |

потерь, в одной админке). C–E — то, чего у v1 не было.
