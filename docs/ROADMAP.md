# План переноса

Порядок — от самого маленького клиента к самому большому, по одному, с
откатом одной командой (`docs/MIGRATION.md`). Каждая фаза самостоятельно
полезна и не ломает предыдущие.

Правила из `frogflow/docs/v2/README.md` действуют: база не трогается, v1 и
v2 работают одновременно, поломку у живого клиента чиним в v1, готовность
меряется проверками из `docs/inherited-knowledge.md`, а не ощущением.

## Фаза 1 — фундамент ✔

Арендатор из запроса, per-request JWT, шифрование токенов, реестры модулей и
ниш, вебхуки, крон вебхуков, API оператора. Готово, `npm run check` зелёный.

## Фаза 2 — цифровой магазин в Telegram ✔ (минимальный контур)

Каталог → корзина → страна → телефон → заказ → реквизиты → чек → продавец →
выдача. Первый клиент на v2 — самый маленький магазин цифровых материалов
без платных модулей.

Осталось внутри фазы, по описи:

## Фаза 3 — оплата и физические товары ✔

Сделано: Robokassa из бота (`/api/robokassa/<bot_id>/<result|success|fail>`,
подпись с `Shp_bot`, настройки в админке), физический чекаут целиком (тип
получения, дата с `lead_time_days`, зоны и комиссия, адрес, примечание,
задаток и `on_receipt`), статусы `accepted → in_production → ready →
delivered` в боте и админке, напоминание за сутки покупателю и продавцу
(`/api/cron/fulfillment-reminder`), автопроверка чеков (Google Vision +
текст из PDF, правила в `src/core/receipts/pure.ts`, переключатель и
счётчик в настройках).

Как было в v1: Robokassa (`robokassa.server.ts`, колбэки `result/success/fail`, подпись по
`robokassa_test_mode`, не по `IsTest`), OCR чеков (Google Vision, `proof_auto`
для RU/KZ), выбор способа оплаты для KZ; физический чекаут (тип получения,
дата с `lead_time_days`, зоны с конвертацией комиссии, адрес, примечание),
статусы `accepted → in_production → ready → delivered`, напоминание за сутки,
`payment_mode = on_receipt`. Ниши `confectionery` и `flowers`.

## Фаза 4 — Zernio: Instagram Direct и WhatsApp ✔ (консультант, чат, магазин)

Сделано: адаптер `src/channels/zernio` — разбор события, покупатель с
синтетическим `telegram_id`, реплика в «Чат» и перехват менеджером из
панели, ИИ-консультант (общий с Telegram, `src/core/consultant`) с проверкой
«менеджер отвечает из приложения» по хвосту переписки, заявка продавцу в
Telegram, ответ менеджера из панели через Zernio, `Idempotency-Key` из
контекста события, журнал `zernio_logs` с итогом обработки. Аккаунты клиента
— в `bots.settings.zernio.account_ids` (ставит оператор), ключ API Zernio
один на платформу.

Магазин в переписке (`dm_shop` / `wa_shop`, `shop-flow.ts` + `shop.server.ts`):
каталог и товары нумерованными списками, номер товара из поста («018»,
«№18»), карточка с фото и кнопками (до трёх), корзина с «убрать N»,
оформление (страна номером/названием/кодом, телефон только для физического
заказа, способ и дата получения, зона/адрес, пожелания), реквизиты с QR
или ссылка Robokassa, чек вложением с автопроверкой OCR, выдача ссылками в
ту же переписку (и по кнопке продавца в Telegram, и из админки),
«мои заказы», выход словом на любом шаге, команды по целому сообщению,
жалоба на оплату — сразу человеку, подавление повторов одного ответа.

Подключение из админки (карточка «Instagram и WhatsApp» в настройках,
`channels/zernio/connect.server.ts`): у клиента свой профиль Zernio,
ссылка авторизации с возвратом на `/admin/settings?zernio=connected`,
синхронизация аккаунтов профиля в `bots.settings.zernio` (снимок для
панелей + `account_ids` для вебхука; ручные id оператора сохраняются).
Вебхук платформы — один на ключ Zernio, чинится кроном `ensure-webhook`,
чужой деплой (v1 клиента) без `force` не перетягивается.

WhatsApp-рассылки шаблонами Meta (`wa_broadcasts`): та же очередь
`broadcasts`/`broadcast_recipients` с `channel = whatsapp` — аудитория из
`bot_users.platform = whatsapp` (номер из `contact_phone` или `wa_<номер>`,
минус `opt_out` и `whatsapp_bot_excluded_phones`), отправка через
`POST /inbox/conversations` с `templateName` (`channels/zernio/jobs.ts`),
коды Meta «не в WhatsApp» (131021/131026) считаются как «заблокировали».
Шаблоны — локальная копия `whatsapp_templates` (`core/whatsapp/templates.ts`):
синхронизация из Meta и заявка на новый шаблон из админки
(`channels/zernio/templates.server.ts`), вердикт ревью — вебхуком
`whatsapp.template.status_updated`. Крон `broadcast` гоняет пакеты Telegram
и WhatsApp по одному на клиента; в WhatsApp нет «себе на пробу».

Автоматизация комментариев Instagram (модуль `instagram`): правила
Comment-to-DM живут у Zernio (`/comment-automations`), наши дополнения —
двухшаговая DM, текст второго сообщения, публичная просьба написать в
директ — в `app_settings.ig_comment_automations_meta` тем же ключом, что в
v1 (клиент переезжает без потери настроек). Чистые правила —
`core/instagram/comment-rules.ts` (совпадение слов, окно 5 минут…6,5 дней,
статусы комментариев, id постов, тело правила), оркестрация —
`channels/zernio/automations.server.ts`: `comment.received` → второе
сообщение с кнопками (или очередь `two_step_dm_pending` в `zernio_logs`,
доставка первым же DM покупателя), крон `comment-dm-fallback` раз в 15
минут дошлёт пропущенные private-reply с эскалацией (inbox в существующий
диалог, HUMAN_AGENT, публичный ответ, просьба написать первым; журнал
`comment_dm_fallback_sends`), догоняющая рассылка из `/admin/instagram`.
Таблицы `comment_automation_settings` и `zernio_automations` в живой базе
нет — не используются.

Новому покупателю магазин в Direct/WhatsApp первым делом показывает выбор
языка на четырёх языках (`languagePickerText`, `needsLocalePick`); после
двух нераспознанных ответов — язык магазина и каталог, шаг не держит
человека вечно. Повторно — по слову «язык».

В WhatsApp разделы, товары, страна и языки — списками Meta (interactive
list, `whatsappList` в `shop-flow.ts`, до десяти строк с навигацией):
строка несёт тот же postback, что кнопка (`CAT:`, `PROD:`, `CART`), а шаг
сценария — `STEP:<n>`, который разбирается как набранная цифра. В
Instagram по-прежнему нумерованный текст и три кнопки.

Осталось: нативный каталог Meta (`order` из корзины WhatsApp), добор
`pending`, публикация постов и сторис через Zernio.

Консультант ниши `consultant*` из v1 (леджер `consultant_message_runs`, курс
ВТБ через relay, импорт каталога из Sheets/XLSX) — заменён общим
консультантом v2; специфика BOVI переносится по запросу клиента.

## Фаза 5 — веб: панель оператора и админка ✔ (первый выпуск), Mini App, витрина

Сделано и проверено в браузере на живой базе (Playwright, продакшен-сборка):

- **Панель оператора** `/operator`: вход учёткой платформы, список клиентов
  со статистикой (RPC `operator_bot_stats`), карточка клиента: пауза и
  возобновление, архив, ниша, владелец, заметки, текст паузы; модули с
  зависимостями и ценами из реестра; подключение Telegram токеном
  (getMe → шифрование → `bots.bot_token`), переключатель «обслуживает эта
  платформа» с установкой вебхука и его состоянием; короткий адрес, свои
  домены, аккаунты Zernio; логин и пароль продавца; сообщение владельцу;
  журнал `bot_events`. Онбординг формой — Vercel не нужен.
- **Админка продавца** `/admin`: вход по логину магазина
  (`bots.settings.admin`, scrypt), обзор, заказы с фильтрами и карточкой
  (чек, подтверждение и выдача, отклонение, статусы физического заказа,
  напоминание об оплате, заметка), товары (список, редактор: категории,
  цены по странам, варианты, фото и файлы материалов с загрузкой в
  хранилище под префиксом клиента), категории деревом, покупатели с
  блокировкой, способы оплаты по странам с QR, настройки, модули с заявкой
  на подключение.
- Сессия одна на платформу (`ff-session`), CSRF-middleware на серверных
  функциях, антибрут входа через таблицы `*_login_attempts`.

- **Витрина и Mini App** `/s/<slug>`: каталог, товар с вариантами, корзина
  в браузере, передача корзины в бота (`web_cart_handoffs`, `wc_<token>`),
  чекаут прямо из Mini App по `initData`, юридические страницы
  `/s/<slug>/legal/<doc>`, кнопка меню бота «🛍 Магазин».
- **Регистрация продавца** `/signup` (`SIGNUP_ENABLED`) и подключение
  Telegram токеном из админки.
- **Скидки** `/admin/discounts`: промокоды, сертификаты; баллы лояльности.
- **Рассылки** `/admin/broadcasts`: текст, фото, кнопки товаров и каталога,
  аудитории с живым счётчиком, пробная отправка себе, история с прогрессом и
  остановкой; порог напоминания о брошенной корзине.
- **Аналитика** `/admin/analytics`: 7/30/90 дней с дельтой к прошлому
  периоду, выручка/заказы/покупатели по дням, топ товаров, каналы, статусы;
  у каждого графика табличный вид.

- **Чат с менеджером** `/admin/chat`, **выгрузка в Excel** заказов и
  покупателей, отзывы и реферальная программа в боте, умный поиск, OCR чеков.
- **Оператор**: очередь заявок на модули `/operator/requests` — включить
  и уведомить владельца одной кнопкой.

- **Первые шаги** на обзоре: бот, товар, оплата, уведомления, реквизиты,
  тестовый заказ — с прогрессом, скрываются по желанию.
- **Импорт и экспорт каталога** CSV на странице товаров: русские и
  английские заголовки, предпросмотр (создать / обновить / непонятые
  колонки / ошибки построчно), категории по имени, обновление только
  присланных полей; выгрузка в том же формате с id.

- **Локализация админки** (`app/i18n/admin.ts`): словарь ru/kk/en/uz с
  откатом на русский, язык магазина в `app_settings.admin_locale`, приходит
  в маршрутный контекст (`shop.locale`) — SSR и клиент совпадают; даты и
  числа через `intlLocale`. Переведены навигация, вход (язык запоминается в
  браузере), обзор, заказы и карточка заказа, товары с импортом,
  покупатели, категории, модули. Ещё по-русски: настройки, рассылки,
  Instagram, VIP, скидки, консультант, аналитика, чат, редактор товара —
  ключи добавляются по мере перевода.

- **Команда и роли** (`core/auth/roles.ts`): владелец (учётка от
  оператора) заводит в настройках менеджеров и пользователей «только
  просмотр»; логины уникальны на платформе, хранятся в
  `bots.settings.admin.users`; роль лежит в сессии, серверные функции
  изменений требуют роли не ниже менеджера, настройки/оплата/модули/команда
  — только владельца; действия в истории заказа подписаны логином.

Дальше в этой фазе: перевод остальных разделов админки, аудит действий
вне заказов.

## Фаза 6 — VIP-бот ✔, ретеншн ✔

Рассылки Telegram уже сделаны (фаза 5): `/api/cron/broadcast` раз в минуту,
по 25 сообщений на клиента, клиенты параллельно. WhatsApp-рассылки — вместе
с Zernio в фазе 4.

VIP-подписки ✔ (модуль `vip`): второй токен клиента в
`bots.settings.vip.token_enc` тем же шифрованием, вебхук
`/api/telegram/<bot_id>/vip` со своим секретом, `ensure-webhook` чинит и
его. Ядро `src/core/vip` (арифметика v1 с тестами: окно инвайта, тест-режим
в минутах, стыковка продления, ±дни; операции через интерфейс группы —
ядро не знает Telegram), бот `src/channels/telegram/vip` (тарифы, первый
вход, скрытые тарифы по ссылке `?start=t_<id>`, чек фото/файлом,
подтверждение кнопками продавца, статус, язык на четырёх), крон
`/api/cron/vip` каждые 10 минут (два напоминания, исключение истёкших),
страница `/admin/vip` (подключение бота, настройки, тарифы, подписчики с
подтверждением, ±дни, переотправкой ссылки, исключением, ручным
добавлением). Живой тест ядра с подменённой группой.

Мониторинг ✔: крон `health` раз в 15 минут пишет снимок каждого бота на v2
(вебхук на нашем адресе, очередь обновлений, последняя ошибка Telegram) в
`bot_health_snapshots`; в списке клиентов — колонка «Здоровье», в карточке —
аптайм за 14 дней и интервалы простоя, «Проверить сейчас».

Ретеншн ✔: `/api/cron/retention` раз в сутки, один проход на всех клиентов
(`src/core/retention/retention.ts`): `zernio_logs` (30 дней, сбои — 180),
`manager_chat_messages` (90), `admin_login_attempts` и
`operator_login_attempts` (90), `bot_events` (180), `bot_health_snapshots`
(30), `broadcast_recipients` по дате кампании (90). Порции по 2000 строк,
удаление по 150 id за запрос — список id живёт в строке запроса PostgREST.
Живой тест на демо-клиенте.

## Фаза 7 — v1 выключена

Все клиенты `served_by = "v2"`, проекты Vercel v1 удалены (иначе их крон
`ensure-webhook` попытается забрать бота обратно — в v1 есть `ownsWebhook`,
но лучше не проверять), репозиторий v1 архивируется. Только после этого
можно менять схему: `bots.bot_token` → обязательное шифрование, `app_url`
и `internal_secret` — удалить, `story_product_tags` — привести к общему виду.
