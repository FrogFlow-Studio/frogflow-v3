# План переноса

Порядок — от самого маленького клиента к самому большому, по одному, с
откатом одной командой (`docs/MIGRATION.md`). Каждая фаза самостоятельно
полезна и не ломает предыдущие.

Правила из `frogflow/docs/v2/README.md` действуют: база не трогается, v1 и
v2 работают одновременно, поломку у живого клиента чиним в v1, готовность
меряется проверками из `docs/inherited-knowledge.md`, а не ощущением.

## Фаза 1 — фундамент ✔

Арендатор из запроса, per-request JWT, шифрование токенов, реестры модулей и
ниш, вебхуки, крон вебхуков, API оператора. Готово, `npm run check` зелёный.

## Фаза 2 — цифровой магазин в Telegram ✔ (минимальный контур)

Каталог → корзина → страна → телефон → заказ → реквизиты → чек → продавец →
выдача. Первый клиент на v2 — самый маленький магазин цифровых материалов
без платных модулей.

Осталось внутри фазы, по описи:

| `gift_certificates`                | `gift-certificates.ts`              | ✔ бот + админка             |

## Фаза 3 — оплата и физические товары ✔

Сделано: Robokassa из бота (`/api/robokassa/<bot_id>/<result|success|fail>`,
подпись с `Shp_bot`, настройки в админке), физический чекаут целиком (тип
получения, дата с `lead_time_days`, зоны и комиссия, адрес, примечание,
задаток и `on_receipt`), статусы `accepted → in_production → ready →
delivered` в боте и админке, напоминание за сутки покупателю и продавцу
(`/api/cron/fulfillment-reminder`), автопроверка чеков (Google Vision +
текст из PDF, правила в `src/core/receipts/pure.ts`, переключатель и
счётчик в настройках).

Как было в v1: Robokassa (`robokassa.server.ts`, колбэки `result/success/fail`, подпись по
`robokassa_test_mode`, не по `IsTest`), OCR чеков (Google Vision, `proof_auto`
для RU/KZ), выбор способа оплаты для KZ; физический чекаут (тип получения,
дата с `lead_time_days`, зоны с конвертацией комиссии, адрес, примечание),
статусы `accepted → in_production → ready → delivered`, напоминание за сутки,
`payment_mode = on_receipt`. Ниши `confectionery` и `flowers`.

## Фаза 4 — Zernio: Instagram Direct и WhatsApp ✔ (консультант и чат)

Сделано: адаптер `src/channels/zernio` — разбор события, покупатель с
синтетическим `telegram_id`, реплика в «Чат» и перехват менеджером из
панели, ИИ-консультант (общий с Telegram, `src/core/consultant`) с проверкой
«менеджер отвечает из приложения» по хвосту переписки, заявка продавцу в
Telegram, ответ менеджера из панели через Zernio, `Idempotency-Key` из
контекста события, журнал `zernio_logs` с итогом обработки. Аккаунты клиента
— в `bots.settings.zernio.account_ids` (ставит оператор), ключ API Zernio
один на платформу.

Осталось: магазин в Direct/WhatsApp — `direct-flow.ts` (чистый разбор, 57
проверок — переносится первым), `direct-purchase.server.ts` (состояние
диалога, заказ по факту чека, выдача письмом), каталог списками WhatsApp,
шаблоны Meta вне 24-часового окна и WhatsApp-рассылки, добор `pending`,
`account.disconnected`, подключение аккаунта из админки (connect-URL Zernio),
автоматизация комментариев Instagram.

Консультант ниши `consultant*` из v1 (леджер `consultant_message_runs`, курс
ВТБ через relay, импорт каталога из Sheets/XLSX) — заменён общим
консультантом v2; специфика BOVI переносится по запросу клиента.

## Фаза 5 — веб: панель оператора и админка ✔ (первый выпуск), Mini App, витрина

Сделано и проверено в браузере на живой базе (Playwright, продакшен-сборка):

- **Панель оператора** `/operator`: вход учёткой платформы, список клиентов
  со статистикой (RPC `operator_bot_stats`), карточка клиента: пауза и
  возобновление, архив, ниша, владелец, заметки, текст паузы; модули с
  зависимостями и ценами из реестра; подключение Telegram токеном
  (getMe → шифрование → `bots.bot_token`), переключатель «обслуживает эта
  платформа» с установкой вебхука и его состоянием; короткий адрес, свои
  домены, аккаунты Zernio; логин и пароль продавца; сообщение владельцу;
  журнал `bot_events`. Онбординг формой — Vercel не нужен.
- **Админка продавца** `/admin`: вход по логину магазина
  (`bots.settings.admin`, scrypt), обзор, заказы с фильтрами и карточкой
  (чек, подтверждение и выдача, отклонение, статусы физического заказа,
  напоминание об оплате, заметка), товары (список, редактор: категории,
  цены по странам, варианты, фото и файлы материалов с загрузкой в
  хранилище под префиксом клиента), категории деревом, покупатели с
  блокировкой, способы оплаты по странам с QR, настройки, модули с заявкой
  на подключение.
- Сессия одна на платформу (`ff-session`), CSRF-middleware на серверных
  функциях, антибрут входа через таблицы `*_login_attempts`.

- **Витрина и Mini App** `/s/<slug>`: каталог, товар с вариантами, корзина
  в браузере, передача корзины в бота (`web_cart_handoffs`, `wc_<token>`),
  чекаут прямо из Mini App по `initData`, юридические страницы
  `/s/<slug>/legal/<doc>`, кнопка меню бота «🛍 Магазин».
- **Регистрация продавца** `/signup` (`SIGNUP_ENABLED`) и подключение
  Telegram токеном из админки.
- **Скидки** `/admin/discounts`: промокоды, сертификаты; баллы лояльности.
- **Рассылки** `/admin/broadcasts`: текст, фото, кнопки товаров и каталога,
  аудитории с живым счётчиком, пробная отправка себе, история с прогрессом и
  остановкой; порог напоминания о брошенной корзине.
- **Аналитика** `/admin/analytics`: 7/30/90 дней с дельтой к прошлому
  периоду, выручка/заказы/покупатели по дням, топ товаров, каналы, статусы;
  у каждого графика табличный вид.

- **Чат с менеджером** `/admin/chat`, **выгрузка в Excel** заказов и
  покупателей, отзывы и реферальная программа в боте, умный поиск, OCR чеков.
- **Оператор**: очередь заявок на модули `/operator/requests` — включить
  и уведомить владельца одной кнопкой.

Дальше в этой фазе: локализация админки (kk/en/uz), роли и несколько
пользователей у одного магазина.

## Фаза 6 — VIP-бот, ретеншн

Рассылки Telegram уже сделаны (фаза 5): `/api/cron/broadcast` раз в минуту,
по 25 сообщений на клиента, клиенты параллельно. WhatsApp-рассылки — вместе
с Zernio в фазе 4. Второй токен (VIP) — в `bots.settings.vip.token_enc` тем
же шифрованием, вебхук `/api/telegram/<bot_id>/vip`. Ретеншн `zernio_logs`, `manager_chat_messages`, `admin_login_attempts`,
`bot_health_snapshots` — один крон на всех.

## Фаза 7 — v1 выключена

Все клиенты `served_by = "v2"`, проекты Vercel v1 удалены (иначе их крон
`ensure-webhook` попытается забрать бота обратно — в v1 есть `ownsWebhook`,
но лучше не проверять), репозиторий v1 архивируется. Только после этого
можно менять схему: `bots.bot_token` → обязательное шифрование, `app_url`
и `internal_secret` — удалить, `story_product_tags` — привести к общему виду.
