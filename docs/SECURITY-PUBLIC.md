# Публичные серверные функции: кто что может

Серверные функции, которые отвечают без сессии продавца и оператора: вход, регистрация, витрина,
страница заказа по ссылке, сертификат, площадка, Mini App, приглашения. Любой может вызвать их
по HTTP напрямую, поэтому защита живёт в самой функции, а не на странице.

Таблица ниже сверяется с кодом тестом `src/app/public-functions.test.ts`:

- каждая функция без гварда (`requireAdmin*`, `requireOperator`, `guard()`) из `src/app/**/*.functions.ts`
  обязана иметь здесь строку, и каждой строке соответствует функция: новая публичная функция без строки
  валит тест;
- в колонке «Что проверяет» названа проверка, которую тест находит в теле функции (или в файле после `::`);
- колонка «Лимит» называет защиту от потока и перебора, которую тест находит в коде, или объясняет, почему
  лимит не нужен (`нет: …`);
- колонка «Тест» указывает файл и строку, которые тест находит в нём: поведение проверено там.

Поведение, общее для всех строк, проверяет `src/app/public-access.test.ts`: закрытая или чужая витрина
отвечает так же, как несуществующая (клиент прежней платформы невидим); неверная и чужая подпись заказа
не отличается от несуществующего заказа; перебор ограничен.

## Как читать колонки

- **Что проверяет**: доступ. `storefrontOpen` — магазин на v2, не в архиве, нужный модуль включён (иначе
  «не найден», как у несуществующего); `verifyOrderAccess`, `openCourse`, `verifyPartnerToken` — подпись или
  секрет в ссылке; `initData` — подпись Telegram токеном бота магазина; `verifyChallenge` — задача против
  ботов в браузере, решается один раз (`claimChallenge`).
- **Лимит**: `takeWeb`, `takeCourse`, `takeMiniApp` — счётчики в `app_settings` магазина
  (`core/storefront/rate-limit`, `checkout-guard`); `loginDelay` и `loginLocked` — пауза и замок входа;
  `ipHash` — хеш адреса вместо самого адреса.
- **Что отдаёт**: чего не должно быть в ответе: чужих данных, телефонов, адресов и почты покупателей,
  секретов, признаков «такой логин или заказ есть».

## Правило для новой публичной функции

1. Начать с проверки доступа: `storefrontOpen(t, part)` для витрины, подпись для ссылки, `initData` для
   Mini App. Клиент прежней платформы (`servedByV2` ложно), архивный и неизвестный магазин отвечают одинаково.
2. Любая запись или дорогое чтение — за лимитом; публичная форма — ещё и за задачей для браузера.
3. Ответ на неверный секрет, чужой секрет и несуществующий объект — один и тот же, без подсказки.
4. Добавить строку сюда и тест на неверный токен, повтор и перебор.
