# Переключение прода с v2 на v3

Для Якова. v3 — это v2 (коммит 53b1f6a) плюс доработки; схема базы та же,
база та же, клиенты те же. Переключение — смена проекта Vercel за доменом, а
не перенос данных. Всё, что ждёт слова Якова, помечено **«ждёт слова Якова»**:
без него ничего не трогаем (v2 заморожен, Vercel и живая база — тоже).

## Что нового в v3 относительно v2

Продавцу и покупателям:

- **Онлайн-школа:** тарифы ниши на `/for/courses`, групповой чат потока,
  кураторы и нагрузка на странице ДЗ, перевод ученика в другой поток, ручное
  продление доступа, выгрузка учеников в CSV, сертификат (PDF) и страница
  проверки, голосовые и видео в домашних заданиях, чеклист запуска школы.
- **Деньги и чеки:** сверка получателя в автопроверке чека, чек старше 3
  суток уходит продавцу, ручная правка баллов с журналом, ошибки чтения базы
  в оплатах, возвратах и остатках больше не превращаются в «нет данных».
- **Кроны не дублируют сообщения**, если идут одновременно (поздравления,
  VIP, дайджест, уведомления о заказах, подписки платформы, удаление магазина).
- **Сайт:** SEO-статьи `/blog` на 4 языках, метатег Яндекс Вебмастера.

Оператору:

- **«Лиды»:** воронка, ИИ-оценка, черновик первого сообщения, автопоиск и
  ежедневный крон. Крон **выключен** флагом `v3_lead_cron` в карточке
  «Конвейер лидов», включать только когда v1 перестал вести лидов.
- **`/api/health`** отдаёт `version: 3` и список переменных окружения
  (только «задана / нет»); без обязательной переменной отвечает `ok: false`.
- **Режим предпросмотра** `PREVIEW_READONLY=1` (только для превью-деплоев):
  кроны и вебхуки не работают, отправка и платные вызовы (ИИ, Vision, ApiPay,
  push) выключены.
- Новый крон в `vercel.json`: `/api/cron/leads` (`0 6 * * *`, это UTC: 11:00 по Алматы, ежедневно).

Для разработчика: `npm run verify` (lint, типы, тесты, сборка, сертификат из
собранного сервера, проверка вывода под Vercel), `npm run smoke` (поднять
собранный сервер на подставной базе и пройти основные адреса).
Подробнее — `docs/ROADMAP.md`, раздел «v3».

## Переменные окружения

Новый проект Vercel для v3 создаётся пустым, переменные в него переносятся
**один в один из проекта v2** (Settings → Environment Variables → скопировать
значения; значения в чат и в репозиторий не пишем). Две переменные новые:

| Переменная            | Нужна                                          | Что делает                                                                                                       |
| --------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `YANDEX_VERIFICATION` | по желанию                                     | метатег подтверждения сайта в Яндекс Вебмастере                                                                  |
| `PREVIEW_READONLY`    | на проде не задавать; на время шагов 2–3 — `1` | `1` отключает работу кронов и вебхуков (они отвечают 200 без работы), отправки выключены; health и вход работают |

Обязательные (без них платформа не стартует): `APP_URL`, `SUPABASE_URL`,
`SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_JWT_SECRET`,
`SECRETS_KEY`, `SESSION_SECRET`, `WEBHOOK_SECRET`, `CRON_SECRET`.
`SECRETS_KEY` и `SESSION_SECRET` должны быть **те же, что в v2**: иначе токены
ботов в базе не расшифруются, а продавцы разлогинятся.
Остальные включают функции (оператор, Zernio, ApiPay, ИИ, Vision, почта, push,
Sentry, курс ВТБ): полный список с пояснениями — `src/lib/env-report.ts`.
После деплоя `/api/health` покажет, чего не хватает.

## Порядок переключения

Делать в тихий час (см. «Тихий час» в `docs/MIGRATION.md`). Каждый шаг ниже
**ждёт слова Якова** на сам день переключения.

1. **Снимок «до».** Копия базы по `docs/BACKUP.md` и запись: какие клиенты на
   v2 (`served_by = "v2"`). v3 пойдёт по тем же клиентам — отдельно никого
   переключать не нужно.
2. **Проект v3 в Vercel**: репозиторий `Frogflow-v3`, ветка `master`, регион
   и команды сборки берутся из `vercel.json`. Скопировать переменные (раздел
   выше) и **добавить `PREVIEW_READONLY=1`**: первый деплой на master — это
   production проекта, его кроны пошли бы по живой базе рядом с кронами v2.
   Домен не трогать.
3. **Проверить временный адрес**, только чтением:
   - `/api/health` → `ok: true`, `version: 3`, `missingRequired` пуст;
   - главная, `/for/courses`, `/blog`, `/sitemap.xml`, витрина демо `/s/<адрес>`;
   - вход оператора и продавца демо-клиента.
     При `PREVIEW_READONLY=1` кроны и вебхуки v3 ничего не делают, так что
     шаги 2–3 можно не торопить.
4. **Выключить кроны проекта v2** (Vercel → проект v2 → Settings → Cron Jobs →
   Disable), затем в проекте v3 **убрать `PREVIEW_READONLY` и сделать
   Redeploy**. Окно, когда кроны идут в обоих проектах, сводится к минутам
   Redeploy; v3 к нему готов (отметка ставится до отправки).
5. **Переключить домен** `www.frogflow.tech` с проекта v2 на проект v3
   (Vercel → Domains). Проект v2 **не удаляем и не ставим на паузу** — он
   нужен для отката.
6. **Вебхуки.** Telegram: крон `ensure-webhook` раз в час сам ставит вебхук на
   домен; не ждать часа — запустить его вручную (`/api/cron/ensure-webhook` с `CRON_SECRET`). Instagram и
   WhatsApp: «Вебхук Zernio» → «Привязать» у каждого клиента на них.
   ApiPay: адрес вебхука не меняется, домен тот же.
7. **Проверить прод**, только чтением:
   - `/api/health` на домене: `ok: true`, `version: 3`;
   - `npm run smoke` на прод **не направляется**: он поднимает собранный
     сервер на подставной базе (запускать до переключения, у разработчика
     или в `npm run verify`). Прод проверяем руками: главная, `/s/…` у Print
     KZ Art и Education Bot, вход продавца Education Bot;
   - в Sentry за первые 15 минут нет новых ошибок, а сообщений покупателям
     дважды не пришло (смотреть историю заказа).
8. **Через сутки:** убедиться, что ночные кроны (`retention`, `vip`, подписки)
   прошли один раз; затем — по слову Якова — включить `v3_lead_cron`, если
   лидов больше не ведёт v1.

## Откат

Откат — вернуть домен на проект v2 (шаг 5 наоборот) и включить его кроны.
Данные при этом остаются в той же базе, но v2 **не знает** части того, что
писал v3. Перечень ведёт `src/core/courses/compat-v2.test.ts` (реестр
`V3_ONLY`); если отката не было, на это можно не смотреть.

| Что v3 записал                                             | Что произойдёт на v2                                                                                                             |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `course_run_*`.`until` (ручное продление доступа)          | v2 закроет канал по сроку тарифа, а не по продлению; при отметке урока потеряет поле. Продлённым ученикам вернуть доступ вручную |
| поток `chat` (групповой чат потока)                        | v2 сотрёт его при следующем сохранении курса в админке; новых ссылок в чат не выдаст, исключать из чата не будет                 |
| `course_invg_*` (ссылки в чаты потоков)                    | v2 их не читает: из чатов потоков по окончании срока никого не исключит                                                          |
| `course_cur_*` (кураторы)                                  | v2 не закрепляет работы за кураторами                                                                                            |
| `course_cert_no` (счётчик сертификатов)                    | v2 сертификаты не выдаёт; выданные остаются                                                                                      |
| события `access_extended`, `cohort_moved` в истории заказа | v2 показывает голое название события, на работу не влияет                                                                        |
| флаг `v3_lead_cron` и данные «Лидов»                       | v2 их не читает; **до отката выключить `v3_lead_cron`**                                                                          |

Всё остальное v3 пишет в форматах v2 и откат переносит без потерь. Починить
v2 так, чтобы он сохранял неизвестные поля прохождения и учитывал `until` в
кроне окончания доступа, можно маленькой правкой `parseRun` и
`core/courses/reminders.server.ts` — **ждёт слова Якова** (v2 заморожен).
Если школа на v3 ещё не запускалась (первый клиент — середина октября),
таблица пуста и откат чистый.

После отката: проверить `/api/health` на проекте v2, вебхуки (шаг 6) и в
течение суток следить, что кроны v2 идут по одному разу.
