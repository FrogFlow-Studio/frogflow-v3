## 2. Как Яков видит v4 (важно)

- v4 — это **скачок всей платформы** для всех магазинов, а не переезд одного клиента. Этапы описывать через то, что становится лучше, и не строить рассказ вокруг Копилки.
  1. **Мозг:** один ИИ-сотрудник на все каналы.
  2. **Каналы:** Telegram, Instagram, WhatsApp.
  3. **Деньги:** все оплаты в одной книге, ИИ-подсказка по чеку.
  4. **Рабочее место продавца:** около 10 экранов вместо 60, экран «Сегодня», строка команд ИИ, решения из Telegram.
- ИИ — **платная надстройка, включается флажком на магазин** (`shops.ai_features.buyer`). Магазин без ИИ работает как в v3: кнопки и сценарии, Comment-to-DM по правилам. Новый «путь без ИИ» не придумывать: «у нас и так всё работает». Самый успешный клиент (AATeach) продаёт без ИИ.
- Ничего из v3 не терять. Порядок: опись → экзамен на старых диалогах → «тень» → переезд по одному клиенту с откатом за 10 минут. Новое включается флажками.
- Общение: по-русски, коротко, Яков выгорает. Серию правок проверять **один** раз в конце: один precheck, один gate, один PR.

## 4. Что НЕ сделано

1. **Входов нет.** Ни одно сообщение из Telegram, Instagram или WhatsApp в мозг v4 пока не приходит, вебхуки пускают только `served_by = "v2"`. Это этап 2. Ядро готово принять текст, голосовое (`media.load` с байтами) и фото, а также быструю модель (`fastModel`).
2. **Живая модель ни разу не прогонялась.** Все сценарии идут на записанных ответах, ключа API в окружении нет. Прогон `tests/integration/v4-seller-eval.test.ts` (`V4_SELLER_EVAL=1`) стоит около $0,3 и ждёт «да» Якова на бюджет. Насколько хорошо модель продаёт, пока не проверено.
3. **Миграции 001–023 не применены к базе.** Их применяет Яков в SQL-редакторе по порядку. Схему `v4` нужно добавить в Exposed schemas без прав `anon`. В 017–023 правки внесены прямо в файлы, это можно, пока они нигде не применены.
4. Оплаты в книгу v4 (Robokassa, Prodamus, Kaspi-чек, apipay) и ИИ-подсказка по чеку — этап 3.
5. Панель продавца в новом виде — этап 4. Памятка продавцу (`/mnt/project-files/v4/ai-seller-memo.md`) — черновик, пункт 3 в ней зависит от панели.
6. Вне этапа 1, из части 2 плана: ИИ-помощник продавца в Telegram, «учится сам» по ночному прогону, Managed Bots, Mini App (нужно «да» Якова, это меняет решение 24), Telegram Business.
7. Счётчик людей в группе VIP (v3 PR #230) перенести в v4 на этапе курсов, не потерять в описи.
8. На PR v4 висит красная отметка Vercel от проекта «frogflowplatform»: «Account is blocked». К коду она не относится, но Якову стоит проверить, не задевает ли это прод.

## 5. Мои мысли

- **Следующий шаг — этап 2 (каналы), но сначала живой прогон.** $0,3 — самая дешёвая страховка: если модель продаёт плохо, это лучше узнать до того, как подключать к ней каналы. Нужны ключ и «да» Якова.
- **Каналы делать тонкими.** Адаптер только принимает сообщение, скачивает файл, зовёт `runAgent` и отправляет ответ с кнопками. Вся логика остаётся в ядре и роли. В v3 логика размазана по 42 файлам Telegram и 51 файлу Zernio, повторять это нельзя.
- **Магазины без ИИ** на этапе 2 должны получать ровно поведение v3. Это проверяется прогоном золотых диалогов `tests/dialogs` против v4: экзамен «не хуже» до любого переезда.
- **Тень** включать на настоящих сообщениях за счёт платформы (около $0,5–1 в день) и сравнивать с v3 построчно.
- **Риск объёма.** Этап 1 — около 10 тысяч строк, тесты есть на всё, но в боевой работе всплывёт то, чего в тестах нет. Не включать ИИ клиенту без тени и флажка.
- **Опечатки сильнее одной буквы** («Политра») поиск ловит только частично. Триграммы (`pg_trgm`) нужны при каталоге больше 500 товаров (BOVI); расширение в Supabase включается отдельно.

## 6. Как проверять (облачный контейнер)

```bash
env -u SUPABASE_URL -u SUPABASE_SERVICE_ROLE_KEY -u SUPABASE_JWT_SECRET npm run precheck   # «готово к PR»
env -u SUPABASE_URL -u SUPABASE_SERVICE_ROLE_KEY -u SUPABASE_JWT_SECRET npm run gate       # «можно вливать»
npx vitest run src/v4                                                                       # тесты v4
```

Если в облаке Playwright падает с «Executable doesn't exist», нужна ссылка на браузер:

```bash
mkdir -p /opt/pw-browsers/chromium_headless_shell-1194/chrome-linux && \
ln -s /opt/pw-browsers/chromium_headless_shell-1243/chrome-headless-shell-linux64/chrome-headless-shell /opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell && \
cp /opt/pw-browsers/chromium_headless_shell-1243/{INSTALLATION_COMPLETE,DEPENDENCIES_VALIDATED} /opt/pw-browsers/chromium_headless_shell-1194/
```

Один e2e (подсказка PWA витрины, `shop19-v-pwa`) иногда падает и на чистой v4, к этим изменениям он не относится.

Правила, которые нарушать нельзя:

- прод-базу не читать;
- живую модель без «да» не гонять;
- в литералах исходников не использовать неразрывные пробелы;
- каждая строка для продавца и покупателя на 4 языках;
- `process.env` читается только в `src/config/env.ts`.
