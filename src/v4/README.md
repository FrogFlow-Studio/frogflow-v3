## Правила v4 (вдобавок к CLAUDE.md)

1. **Ветка `v4`.** В master не вливается, пока не переедет первый клиент и Яков не скажет «да». Vercel ветку `v4` не собирает (`vercel.json`). master вливается в `v4` обычным merge.
2. **Только схема `v4`.** Таблицы `public` v4 читает при переезде и не пишет никогда (решение 30). Клиент обслуживается v4, только когда `bots.settings.served_by = "v4"`; v3 такого клиента уже не трогает (`servedByV2` ждёт `"v2"`).
3. **Деньги — книга.** Заказ не хранит «оплачено»: это сумма записей книги денег по заказу в его валюте (решения 1, 51, 54, 91). Записи книги не меняются и не удаляются, ошибка исправляется встречной записью.
4. **Ничего не удаляем** (решение 2): заказ истекает, дело закрывается, доступ кончается — статусом и датой.
5. **Строгие статусы и один ключ** (решение 70): статусы — `check` в базе и union в TS из одного списка; покупатель — одна запись с каналами (решение 68).
6. **Гонки — в базе.** «Один раз» обеспечивают уникальные ключи и условные записи в SQL, тест на гонку — на PGlite, не на заглушке.
7. **Никаких клиентов в коде** (решение 49).

## Этап 1: ИИ-продавец

ИИ — платная надстройка магазина: без включённого `ai_features.buyer` магазин работает как в v3 (кнопки и простые ответы), отдельного «пути без ИИ» нет.

| Что             | Где                                                                                                                                                        |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ядро агента     | `src/v4/agent/run.ts` — один проход на ход, режимы live / shadow / test, проверки ответа `agent/checks.ts`, кошелёк: hold → settle с наценкой / release    |
| роль «продавец» | `src/v4/seller/*` — `role.ts` (контекст, запасной ответ, «+»), `tools.ts`, `prompt.ts`, `offers.ts` (код предложения, цены на 72 ч), `readiness.ts`        |
| перенос из v3   | `src/v4/transfer/*` — `planTransfer` (чистая функция + отчёт «проверить»), `applyTransfer`, `readV3Snapshot` (только чтение v3)                            |
| экзамен         | `src/v4/seller/exam.test.ts` — 95 сценариев A01–K06 на записанной модели; живая модель — `tests/integration/v4-seller-eval.test.ts` при `V4_SELLER_EVAL=1` |

Голос, фото, две модели (часть 2 плана, «на голову выше»):

- **Голосовые** — `agent/media.ts`, `agent/speech.server.ts` (Whisper, ключ платформы как в v3). Канал отдаёт ядру байты (ссылка Telegram с токеном в логи не попадает). Входящее пишется до расшифровки (`set_voice_text`): повтор вебхука не платит второй раз. Расшифровка — с баланса ИИ с наценкой (100 мкр$ в секунду), длиннее 5 минут или не разобрали — просьба написать текстом без модели. ИИ выключен — не расшифровываем.
- **Фото** — картинка уходит модели в последнем сообщении покупателя (тип по байтам, до 5 МБ); в журнале только пометка и подпись. Товар на фото — поиск по каталогу; чек или скриншот оплаты — продавцу (`payment`), оплату модель не подтверждает (проверка чека — этап «Деньги»).
- **Две модели** — `agent/route.ts`: простое (приветствие, «спасибо», «где мой заказ», 4 языка) — `FAST_AGENT_MODEL`, остальное, фото и «ок» после кнопки — сильная. Ответ быстрой не прошёл проверку — исправляет сильная. Модель каждого вызова — в `ai_usage.model`.

Миграции этапа:

- `017` — разговор покупателя: факты (`remember_fact`), язык, голосовые и фото (`kind`, `set_voice_text`).
- `018` — кошелёк ИИ: hold/settle/release, дневной предел → дело `ai_limit` раз в день.
- `019` — карточка товара и поиск: совпадение по началу слова, стоп-слова, одна опечатка.
- `020` — предложения с кнопкой «Купить».
- `021` — роль «продавец»: `shops.ai_features` (+`rev`), `default_lang`, знания на проверке, авто-предел, `seller_context_v2`, `seller_readiness`.
- `022` — перенос из v3 (анкета, знания, флажки, история, блоки, описания и фото товаров): `transfer_from_v3` (только сервисная роль, одна транзакция, повтор ничего не задваивает), `transfer_catalog`.
- `023` — польза и учёт: кандидаты в экзамен из ответов продавца (Р8), сводка «ИИ стоил / принёс» (`ai_value_report`, Р9), обезличивание покупателя по просьбе (`forget_buyer`, В4), сигналы оператору (`ai_signals`, дело `ai_health`), сверка кошелька в кроне `tick` (`ai_wallet_check`).
- `024` — покупка до замены v3: шлюзы stripe/kaspi/nowpayments в ту же книгу, остаток движениями, шаги физического заказа, урок на доступе, снимок VIP-группы, площадка, розыгрыш, лист ожидания, рассылка, счёт платформы в `book = billing`, предполёт `shop_preflight`. Код — `src/v4/core/platform.ts`, каналы — `src/v4/channels/inbound.ts`. Флаг `served_by` отсюда не ставится.
- `025` — глубина без живой модели: заявка входящего, ответ продавца своим текстом, поиск с триграммами если расширение уже есть, кандидаты экзамена. Вебхук v4 спит, пока флаг не `v4`; живую модель, тень и замену v3 этот этап не включает.

Счётчик людей в VIP-группе из v3 (#230) пишется в `v4.vip_groups` функцией `refreshVipCount` (`src/v4/channels/vip.ts`). Живые подписки считает `vip_active_access`.
