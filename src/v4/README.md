## Где что

| Путь                      | Что                                                                                                       |
| ------------------------- | --------------------------------------------------------------------------------------------------------- |
| `migrations/v4/NNN-*.sql` | схема `v4` в той же базе; каждый файл с `.down.sql` и запросом-проверкой. Применяет Яков в SQL-редакторе. |
| `src/v4/core/*`           | ядро v4: деньги, заказы, дела, доступы, ИИ-продавец. Канала не знает.                                     |
| `src/v4/channels/*`       | адаптеры каналов v4 (переиспользуют клиентов Zernio и Telegram из v3).                                    |
| `src/v4/test/pg.ts`       | настоящий Postgres в памяти (PGlite) с применёнными миграциями v4 для тестов.                             |

## Правила v4 (вдобавок к CLAUDE.md)

1. **Ветка `v4`.** В master не вливается, пока не переедет первый клиент и Яков не скажет «да». Vercel ветку `v4` не собирает (`vercel.json`). master вливается в `v4` обычным merge.
2. **Только схема `v4`.** Таблицы `public` v4 читает при переезде и не пишет никогда (решение 30). Клиент обслуживается v4, только когда `bots.settings.served_by = "v4"`; v3 такого клиента уже не трогает (`servedByV2` ждёт `"v2"`).
3. **Деньги — книга.** Заказ не хранит «оплачено»: это сумма записей книги денег по заказу в его валюте (решения 1, 51, 54, 91). Записи книги не меняются и не удаляются, ошибка исправляется встречной записью.
4. **Ничего не удаляем** (решение 2): заказ истекает, дело закрывается, доступ кончается — статусом и датой.
5. **Строгие статусы и один ключ** (решение 70): статусы — `check` в базе и union в TS из одного списка; покупатель — одна запись с каналами (решение 68).
6. **Гонки — в базе.** «Один раз» обеспечивают уникальные ключи и условные записи в SQL, тест на гонку — на PGlite, не на заглушке.
7. **Никаких клиентов в коде** (решение 49).
